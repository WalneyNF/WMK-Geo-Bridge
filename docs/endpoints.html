Manual de endpoints — WMK Geo Bridge

Documentação completa em português brasileiro · API experimental v0.1.0

Swagger interativoEspecificação OpenAPIGitHub

1. Primeiros passos

1. Instale Python 3.10+ e clone o repositório. 2. No terminal, execute py -3 src/bridge.py. 3. Acesse /health. 4. Abra /docs para a documentação Swagger. 5. Para integrar o Traccar, configure WMK_TRACCAR_TOKEN na mesma sessão antes de iniciar o processo. A porta padrão é 8766; para usar 8767 defina WMK_BRIDGE_PORT=8767 antes da inicialização. Não use duas aplicações na mesma porta.

2. GET /health — diagnóstico

Serve para verificar se o servidor HTTP está respondendo. Não verifica se o Traccar está conectado. Requisição: GET /health. Resposta HTTP 200: {"status":"ok","service":"wmk-geo-bridge","version":"0.1.0"}. Se o navegador não conectar, confirme se o processo está rodando, a porta e se outra aplicação já ocupa a porta.

3. GET /api/v1/capabilities — recursos

Informa schemaVersion, sources (na versão atual somente traccar), traccarConfigured e writeEnabled. HTTP 200 significa que o serviço responde, não que a integração Traccar foi validada. O endpoint não mostra credenciais. Se traccarConfigured=false, a consulta de veículos retornará HTTP 503.

4. GET /api/v1/vehicles — rastreamento

Consulta a API Traccar em /api/devices e /api/positions, associa a última posição por deviceId e retorna JSON com schemaVersion, source, items, count, timestamp. Cada item contém id, deviceId, name, source, simulated e position. A position contém latitude, longitude, speedKmh, heading, timestamp, valid. Velocidade do Traccar é convertida de nós para km/h (multiplicação por 1,852). Sem posição, position=null. simulated=null significa que a ponte não verificou se a posição foi simulada. HTTP 200 sucesso, HTTP 503 sem credencial, HTTP 502 indisponibilidade/erro de autenticação ou resposta inválida do Traccar. Não usa os quatro carros do simulador JSONL da ponte antiga.

5. POST /api/v1/positions — envio externo

Endpoint experimental para demonstrar como aplicações externas podem publicar posições. Configure WMK_BRIDGE_API_KEY no ambiente do servidor antes de iniciá-lo. No cliente envie cabeçalho X-WMK-API-Key e Content-Type: application/json. Corpo: {"id":"carro-exemplo-001","latitude":-22.28,"longitude":-42.53}. Resposta 202: {"accepted":true,"persisted":false,...}. ATENÇÃO: os dados NÃO são salvos, NÃO são enviados ao Traccar e NÃO aparecem em /api/v1/vehicles. HTTP 403 significa escrita desabilitada; 401 chave incorreta; 400 payload inválido; 413 tamanho inválido. Limite do corpo: 16384 bytes.

6. Autenticação do Traccar

Configure WMK_TRACCAR_URL=http://127.0.0.1:8082 e WMK_TRACCAR_TOKEN=TOKEN_VALIDO, ou WMK_TRACCAR_USER e WMK_TRACCAR_PASSWORD. A ponte autentica no Traccar por Bearer ou Basic. Não coloque token em arquivos HTML, no navegador, em scripts versionados ou no README. A implementação atual só permite Traccar em endereço local, por segurança. O endpoint GET de veículos não exige chave própria na ponte: portanto não publique esta versão em rede.

7. Como testar com Swagger UI

Com a API iniciada, abra http://127.0.0.1:8766/docs (ajuste a porta se necessário). Expanda GET /health, clique Try it out e Execute. Confira HTTP 200 e o JSON. Repita em /api/v1/capabilities. Em /api/v1/vehicles, HTTP 503 é esperado sem credenciais; HTTP 502 indica erro de integração. Para testar POST, configure a chave no servidor e use Authorize na interface Swagger; use apenas dados fictícios. O Swagger UI usa CDN externa e precisa de internet para carregar a interface; /openapi.json e este manual continuam disponíveis sem CDN.

8. JavaScript — navegador e Node.js

Em Node.js 18+, execute node examples/cliente.js. Em navegadores, fetch('http://127.0.0.1:8766/health').then(r=>r.json()).then(console.log). Para consumir /api/v1/vehicles, confira response.ok e trate 502/503. A API atual permite CORS somente para http://127.0.0.1:4173 e http://localhost:4173. Para outros sites, use um backend intermediário ou configure origens autorizadas de forma segura; não desative CORS indiscriminadamente.

9. Python — cliente HTTP

Execute py -3 examples/cliente.py com o servidor ativo. O exemplo usa urllib da biblioteca padrão, imprime status HTTP e formata JSON. Para enviar uma posição experimental, configure WMK_BRIDGE_API_KEY na mesma sessão e execute py -3 examples/enviar-posicao.py. A chave precisa coincidir com a do processo servidor, que deve ter sido reiniciado depois da configuração.

10. PHP — integração com sistemas web

Requer PHP 8+ com extensão cURL habilitada. Execute php examples/cliente.php. O exemplo utiliza curl_init, CURLOPT_RETURNTRANSFER, timeouts, cabeçalho Accept: application/json, curl_exec e json_decode. Em sistemas PHP de produção, mantenha segredos no servidor, trate HTTP != 200 e valide os dados antes de exibir no mapa. Um ERP pode consumir as posições sem instalar Cesium ou Traccar localmente, desde que exista um gateway seguro; a versão atual é apenas local.

11. Formato de dados e unidades

latitude: graus decimais de -90 a 90; longitude: -180 a 180; speedKmh: km/h; heading: direção em graus conforme fornecida pelo Traccar; timestamp: data/hora do GPS no formato original recebido; valid: indicador de validade do Traccar. id: identificador textual na ponte; deviceId: ID original. O contrato de resposta utiliza schemaVersion 1.0; a versão do software é 0.1.0. Os exemplos com Nova Friburgo são fictícios.

12. Segurança, privacidade e limitações

A ponte escuta somente 127.0.0.1. Não possui autenticação de leitura, TLS, auditoria, limite de taxa nem armazenamento externo. CORS não é mecanismo de autenticação. Não exponha a porta 8766/8767 na internet, mesmo com firewall. Em uma versão de produção, implementar autenticação e autorização por dispositivo/usuário, HTTPS, controle de acesso, mascaramento de dados sensíveis, retenção e consentimento para dados de localização. A versão atual não fornece dados de congestionamento; veículos isolados não equivalem a medição de fluxo viário.

13. Método de testes e erros

T001: iniciar serviço e testar GET /health e GET /api/v1/capabilities, ambos 200. T002: configurar credenciais Traccar e testar GET /api/v1/vehicles, esperando 200 e dados normalizados. T003: configurar chave de escrita e testar POST fictício, esperando 202 e persisted=false. T004: testar erros 401, 403, 400 e 413. T005: testar clientes JS/Python/PHP. Não avançar se houver falha sem diagnóstico. Os testes unitários estão em tests/ e são executados com py -3 -m unittest discover -s tests -v.
